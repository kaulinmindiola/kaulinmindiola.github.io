FluxPay - Payment Gateway Engine

Núcleo transaccional que procesa transferencias entre cuentas. Muchas solicitudes simultáneas sobre la misma cuenta, o un reintento del cliente, nunca deben producir un saldo incorrecto ni un cobro doble.

A transactional core that processes transfers between accounts. Many simultaneous requests on the same account, or a client retry, must never produce a wrong balance or a double charge.

Relacionado con el endpoint idempotente de órdenes y los reintentos idempotentes del flujo de pagos.

Related to the idempotent order endpoint and the idempotent retries in the payment flow.

Decisiones técnicas
Technical decisions
  • Bloqueo pesimista (SELECT … FOR UPDATE) sobre las cuentas involucradas, en orden fijo para evitar deadlocks.
  • Idempotencia real con Idempotency-Key en Redis: un reintento devuelve la respuesta original sin ejecutar de nuevo.
  • Resiliencia con Resilience4j para que una dependencia lenta no tumbe el servicio.
  • Arquitectura hexagonal: el dominio no conoce Spring ni JPA.
  • Pessimistic locking (SELECT … FOR UPDATE) on the accounts involved, in a fixed order to prevent deadlocks.
  • Real idempotency with an Idempotency-Key in Redis: a retry returns the original response without executing again.
  • Resilience with Resilience4j so a slow dependency can't take the service down.
  • Hexagonal architecture: the domain knows nothing about Spring or JPA.

StreamLedger - Resilient Order Pipeline

Servicio de órdenes que dispara procesamiento asíncrono (reserva de inventario y notificación). Tiene que seguir siendo consistente cuando el trabajo se reparte entre procesos que no comparten transacción.

An order service that triggers asynchronous processing (inventory reservation and notification). It must stay consistent when work is split across processes that don't share a transaction.

Relacionado con la confirmación de pagos por eventos entre microservicios.

Related to event-driven payment confirmation between microservices.

Decisiones técnicas
Technical decisions
  • Transactional Outbox: la orden y su evento se guardan en la misma transacción. Se elimina la doble escritura base de datos + broker.
  • Consumidor idempotente con tabla processed_events: entrega at-least-once + deduplicación = efecto único.
  • Dead Letter Queue: un mensaje que falla N veces se aparta para revisión. No se reintenta sin fin ni se pierde.
  • Límite consciente: no se promete exactly-once; la decisión queda documentada en el README.
  • Transactional Outbox: the order and its event are stored in the same transaction, removing the database + broker dual write.
  • Idempotent consumer with a processed_events table: at-least-once delivery + deduplication = effect applied once.
  • Dead Letter Queue: a message that fails N times is set aside for review. Never retried forever, never lost.
  • Deliberate limit: no exactly-once promise; the decision is documented in the README.

AuthCore - Identity Access Service

Autenticación y autorización para una API multi-workspace. Un usuario con token válido nunca debe leer datos de un workspace al que no pertenece, y una sesión robada debe poder cortarse.

Authentication and authorization for a multi-workspace API. A user with a valid token must never read data from a workspace they don't belong to, and a stolen session must be revocable.

Relacionado con Spring Security, OAuth2 y JWT en servicios de clientes.

Related to Spring Security, OAuth2 and JWT in client services.

Decisiones técnicas
Technical decisions
  • JWT de vida corta + refresh token con rotación; si se reutiliza un refresh token, se invalida toda la familia de la sesión.
  • RBAC por workspace (OWNER · ADMIN · MEMBER · VIEWER), no roles globales.
  • Aislamiento por tenant aplicado en cada consulta, no solo en el controlador.
  • Rate limiting en login con Bucket4j y errores con formato RFC 7807.
  • Short-lived JWT + rotating refresh tokens; reusing a refresh token revokes the whole session family.
  • Per-workspace RBAC (OWNER · ADMIN · MEMBER · VIEWER), not global roles.
  • Tenant isolation enforced on every query, not only in the controller.
  • Rate limiting on login with Bucket4j, and RFC 7807 error responses.
